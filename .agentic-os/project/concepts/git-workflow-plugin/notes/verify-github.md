# Verify report: GitHub App behaviours (PLAN-plugin T1.1)

Run 2026-11-03 against `edotz/git-workflow-sandbox` as the test App (App ID 5593711, installation 178152151). The setup is in `sandbox.md`. Every row ran as the installation token of the App; the developer's login only did setup steps and controls. The script was `check-github.sh` of the session; its raw evidence is not kept in the repository, so each row carries its own evidence.

## Settings every row ran under

- Organisation plan team; private repository; repository-level ruleset `master-protection` on the default branch: deletion, non_fast_forward, pull_request (0 approvals), required status check `check`; the App is bypass actor, mode always. No organisation ruleset applied.
- Squash merge only, `squash_merge_commit_title` PR_TITLE, `squash_merge_commit_message` PR_BODY.
- Installed App permissions, read back from the token: at first administration read, contents write, pull_requests write, metadata read, artifact_metadata read, with no Packages and no Workflows permission. For the second round of L500 and for L467 the App was raised to administration write and packages write, and the installation accepted it (read back before the run). No Workflows permission at any time.

## Findings

- The administration permission of the App has to be write for ruleset sync (L500), shown by a refusal with read and a success with write. The concept decisions D23 (token service design) and D26 (rulesets) take the permission set from this row.
- A package publish to GitHub Packages for npm cannot run as the App even with packages write (L467), so the publish stays a workflow with the built-in token, as the white paper assumes.
- No claim was refuted. The behaviours the release rests on, the bypass push with a tag, the Release as the App, `releases/latest` and `--latest=false`, held on a repository ruleset in a team organisation. They were not run against an organisation ruleset.
- A hook of this project's framework fails open in a temporary clone that is not a project root: it prints a bootstrap error and the commit goes through.
