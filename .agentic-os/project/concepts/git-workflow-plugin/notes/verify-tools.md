# Verify report: tool and ecosystem claims (PLAN-plugin T1.2)

Run 2026-11-03. The tools are the versions the Dockerfile pins today: git-cliff v2.8.0 and splitsh-lite v1.0.1, both downloaded from the URLs of the Dockerfile into fresh directories and run on a throwaway repository. Real project files were read, never changed. Containers: `debian:bookworm-slim` (Debian 12.15) for glibc, `alpine:3.20` (3.20.10) for musl, `composer:2` (Composer 2.11.1, PHP 8.5.12). pnpm 10.11.1, the version `edotz.hh-web` pins in `packageManager`.

## Findings

- The Dockerfile download of splitsh-lite is broken today (404) and cannot serve arm64; the image fix of D34 has to download the `.tar.gz` asset, restrict the platform to linux amd64 or build splitsh-lite itself, and record a checksum computed by the project.
- git-cliff 2.8.0 cannot start a pre-release line and has no `--pre`. The first pre-release version has to come from the CLI (T1.4 settles the rule in its Pre-releases section); the counter after that comes from git-cliff.
- A `version` change in `package.json` leaves `pnpm-lock.yaml` alone for the workspace layout of `edotz.hh-web`, and the ext_emconf writer is a one-line rewrite that holds on all 97 real files.
- No claim was refuted outright; L390, L460, L595 and L786 changed what the plan has to assume.
